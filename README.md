# DVS-эмулятор и вход для спайковых нейронов

[![Открыть в Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/Nek1tos01/dvs-emulator/blob/main/notebooks/demo.ipynb)

Эмулятор читает обычное видео и создаёт события `(x, y, t, polarity)` при
изменении яркости пикселей. События можно сохранить, посмотреть рядом с
исходным видео и подать в LIF-слой на PyTorch.

Я разрабатываю этот проект, чтобы разобраться в событийном зрении и
подготовке данных для спайковых сетей. Генерация событий написана на NumPy,
чтение видео работает через OpenCV. Готовые эмуляторы v2e и ESIM здесь не
используются.

Сейчас проект умеет выполнять прямой проход LIF по сохранённой записи.
Обучения и классификации пока нет. Временная точность ограничена кадрами
исходного видео.

## Быстрый запуск

Понадобится Python 3.11–3.13. Выполните команды в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python demo.py
```

`demo.py` обработает первые 30 кадров примера `Videos/IMG_7181.MP4`,
сохранит события и передаст их в LIF. Скрипт напечатает путь к результатам
в `outputs/`. Для запуска достаточно CPU; отдельное окно не открывается.

## Свое видео и предпросмотр

```powershell
python read_mp4.py --input "Videos/IMG_7181.MP4" --max-frames 30 --max-side 320 --preview
```

Замените путь после `--input`, чтобы открыть своё видео. В окне слева
будет исходный кадр, справа события: ON зелёные, OFF красные. Нажмите
английскую `q`, чтобы остановиться и сохранить накопленные события.
Первый кадр задаёт опору, поэтому справа сначала будет чёрный фон.

Без `--max-frames` обработка идёт до прекращения чтения потока. Без
`--max-side` используется исходное разрешение. Для обработки без окон
используйте режим по умолчанию или `--no-preview`.

`--threshold 0.2` задаёт порог логарифмического контраста, а
`--chunk-frames 5` сохраняет события порциями по пять кадров.
Через `--output outputs/my_run` можно выбрать новый каталог для записи.
Если не указать путь, скрипт создаст каталог с датой и временем в имени.
Существующий каталог он не перезапишет.
Все параметры перечислены в `python read_mp4.py --help`.

## Сохранённые данные

```text
outputs/<video>_<timestamp>/
    manifest.json
    events_part_0.npy
    events_part_1.npy
    ...
```

Каждый файл содержит массив `(N, 4)` типа `float64`. Если событий нет,
форма массива будет `(0, 4)`. Столбцы идут в порядке `x`, `y`, `t`,
`polarity`: время в секундах, полярность `+1` для ON и `-1` для OFF.
Координаты имеют целые значения, хотя хранятся как `float64`.
При обращении к изображению порядок индексов обратный: `[y, x]`.

В `manifest.json` записаны путь к видео, размеры кадров, FPS, порог,
число кадров и событий, размер порции и список файлов в порядке чтения.
Поле `stop_reason` объясняет, почему обработка закончилась:

- `frame_limit`: достигнут лимит `--max-frames`;
- `user_stop`: пользователь нажал `q`;
- `end_of_stream`: OpenCV больше не выдаёт кадры;
- `read_incomplete`: чтение остановилось раньше числа кадров, заявленного
  контейнером. Возможна ошибка декодера или неточный счётчик кадров.

При `read_incomplete` скрипт сохраняет прочитанные данные. Если контейнер
вообще не сообщает число кадров, надёжно отличить конец видео от ошибки
декодирования через этот интерфейс OpenCV нельзя.

Нельзя сортировать имена частей лексикографически: `10` окажется перед `2`.
Загрузчик использует manifest или числовые индексы. Старые записи проекта
без списка `parts` также поддерживаются, если есть `chunk_frames`.

При ошибке скрипт освобождает видеозахват и закрывает окно предпросмотра.
В каталоге могут остаться части без `manifest.json`: загрузчик не примет
такой запуск как готовую запись. Размер порции задаётся в кадрах, поэтому
объём одной части зависит от того, сколько событий возникло.

## Запуск LIF на своей записи

Возьмите путь, напечатанный конвертером, и передайте его через `--run`:

```powershell
python run_snn.py --run "outputs/my_run" --device cpu
```

Вместо `outputs/my_run` укажите каталог, созданный конвертером.
`--gain 0.25` задаёт множитель входа, `--tau 0.05` постоянную времени
мембраны в секундах, `--threshold 1.0` порог нейрона.
`--stats outputs/lif_result.json` сохраняет статистику по шагам; существующий
файл статистики не перезаписывается.

События одного исходного кадра преобразуются в счётчики `(2, H, W)` типа
`float32`: канал 0 — ON, канал 1 — OFF. Повторные события суммируются.
Вход LIF имеет форму `(1, 2, H, W)`, где первая размерность обозначает batch.
Один шаг соответствует `1 / FPS` секунды. Пустые кадры тоже проходят через
нейрон, чтобы мембрана успевала затухать. Её состояние сохраняется между
кадрами и файлами одной записи. Каждое новое видео начинает с нуля.
Загрузчик держит в памяти одну часть записи за раз.

Модель: `v = beta * membrane + gain * counts`,
`beta = exp(-dt / tau)`, спайк при `v >= threshold`, затем вычитание порога.
За шаг каждый нейрон выдаёт 0 или 1. При большом входе остаток после сброса
может остаться выше порога. В `lif.py` есть суррогатный градиент для
будущих экспериментов с обучением, но в текущем демо обучаемых связей нет.

`--device auto` выбирает CUDA при доступности, иначе CPU. При явном
`--device cuda` требуется подходящая установка PyTorch/CUDA. Генерация
событий в NumPy и обработка видео в OpenCV остаются на CPU.

## Ограничения модели

- Все события кадра получают одно время. Эмулятор не восстанавливает
  движение между кадрами и не даёт микросекундной точности настоящей DVS.
- Время оценивается через постоянный FPS; видео с переменной частотой
  кадров требует отдельной модели временных меток.
- Яркость берётся из обычного видео в оттенках серого. Это приближение
  физической интенсивности: гамма, сжатие и автоэкспозиция влияют на события.
- Перед логарифмированием значения ниже 1 заменяются единицей, поэтому
  уровни 0 и 1 неразличимы. Порог одинаковый
  для всех пикселей; шум, рефрактерность и задержки сенсора не моделируются.
- Цветная картинка событий не показывает их количество. Для LIF
  используются числовые счётчики, а не цветная визуализация.
- `float64` для всех четырёх полей прост, но избыточен по объёму.

## Публикация на GitHub

`Videos/IMG_7181.MP4`. `.gitignore` исключает `.venv`, кэш, результаты и

Создайте пустой репозиторий GitHub. Не добавляйте на сайте README,
`.gitignore` или лицензию: нужные файлы уже есть локально, а LICENSE в этот
проект не добавляется. Затем выполните команды в папке проекта:

```powershell
git add .gitignore README.md requirements.txt requirements-dev.txt *.py tests notebooks tools .github Videos/IMG_7181.MP4
git diff --cached --stat
git commit -m "Add video-to-events emulator and LIF demo"
git remote add origin https://github.com/Nek1tos01/dvs-emulator.git
git push -u origin HEAD
```

Если remote уже существует, повторно добавлять его не нужно.
Перед коммитом просмотрите вывод
`git diff --cached --stat`: среди файлов должны быть код и пример видео,
без окружения и результатов запусков.
